# ADR-0001: 단계 0의 숫자·기초잔액·저장 경계

상태: 채택 · 2026-10-03 · 백서 12~15절, 20절의 단계 0에 적용.

## 숫자 표현

금액은 10⁻¹²포인트 정수 원자로 저장합니다. 원자 문자열은 절댓값 최대 50자리이고 선행 0, `-0`, 지수 표기를 허용하지 않습니다. 정확한 금액 입력은 소수 12자리까지 허용합니다. 가격·비율·내부 수량은 문자열에서 직접 Decimal을 만들며 최대 50 유효자리, 입력 96문자, 정규화 지수 -1000~+1000을 지원합니다. Decimal은 정밀도 50, HALF_EVEN, 내부 minE -2000/maxE +2000으로 고정합니다.

이 상한은 자원과 표현 정밀도의 경계입니다. 가격 하한이나 실제 유동성 한도가 아닙니다. 범위 초과는 명시적으로 실패하며 반올림으로 0이나 최저가격을 만들지 않습니다. 정산에서는 가격×수량×비용을 정확한 BigInt 분수로 계산하여 Decimal의 유효자리 반올림이 원자 올림·내림 방향을 바꾸지 않게 합니다. 거래대금이 한 원자 미만이면 정산 오류로 거절합니다. 더 큰 수량으로 한 원자 이상이 되는 작은 가격의 거래는 가능합니다.

입력의 유효 지수는 Decimal 생성 전에 검사하여 라이브러리의 underflow가 비영 값을 0으로 바꾸지 못하게 합니다. 실효이율의 `1+r` 계산이 50자리 정밀도에서 소거되거나 결과가 -100%로 뭉개지는 경우도 표현 오류로 거절합니다.

매수 총 차감은 원자 올림, 매도 순수령은 원자 내림입니다. 경계차는 정확한 `roundingAdjustment`로 반환합니다. 이자·배당 누적 분수는 정확한 분자/양수 분모로 남기고 지급 시 원자 아래 잔액을 이월합니다. 단계 0은 해당 산술·저장 계약만 정의하며 이자·배당 지급 스케줄은 후속 단계입니다.

## 초기 기업 재무

백서의 기업 재무 ‘억 모의원’은 100,000,000포인트를 곱하여 변환합니다. 현금은 총자산에, 이자부 부채는 총부채에 포함됩니다. 초기 배당가능 누적이익은 기초 자기자본의 이익잉여금으로 분류하고 나머지를 납입자본으로 둡니다. 새로운 수익으로 다시 계상하지 않습니다.

백서가 지정하지 않은 비현금 자산은 매출채권·재고·유형자산·무형자산의 회사별 명시적 고정 비율로 분해합니다. 비이자부 부채는 기초 매입채무로 둡니다. 비율은 `SOURCE_COMPANIES`에 포함하며 실제 기업 자료가 아닌 초기화 가정입니다. 총계 및 계정 합계가 일치하지 않으면 초기화를 거절합니다.

이자부 부채는 동일 원금 8개 만기로 나누고 T63, T126, …, T504에 배치합니다. 각 만기 안에서 백서의 고정·변동 비중을 적용합니다. 변동 스프레드는 초기 차입금리에서 초기 정책금리 3%를 뺀 값입니다. 실제 이자 발생과 차환은 단계 2에서 계약대로 구현합니다.

과거 4분기의 합성 참고 실적은 연매출·영업이익과 원금×연 차입금리의 이자를 4등분합니다. 양의 세전이익에만 가상 기업세율 20%를 적용합니다. 합성 네 분기의 누적 순이익과 기초 이익잉여금 차이는 별도 연결 조정값으로 기록하여 이익을 두 번 더하지 않습니다. 이 표는 발생 시점별 실제 이자 스케줄을 실행한 결과가 아닙니다.

## 계좌·저장 경계

신규 계좌의 초기자금 키는 시장과 Discord 사용자 ID의 조합입니다. 별도 Interaction으로 재요청하거나 DB를 재개방해도 10,000포인트는 한 번만 지급합니다. 계좌·금액 양측 전표·처리된 명령 기록은 같은 트랜잭션에서 커밋합니다. 원장은 수정·삭제하지 않고 정정은 역전표로 추가합니다. 기존 계좌 개설 요청은 공개 시장 버전·시세·틱을 바꾸지 않습니다.

같은 명령의 캐시 응답도 현재 원장의 무결성과 해당 명령 순번 당시의 잔액을 확인한 후 반환합니다. 이후 거래가 있으면 원래 응답의 역사적 잔액을 유지하고, 캐시만 손상된 경우에는 오류로 거절합니다.

SQLite는 외래키, WAL(파일 DB), FULL 동기화, 제한된 busy timeout을 사용합니다. 마이그레이션의 버전과 체크섬을 확인하고 알 수 없는 버전 또는 변경된 이력을 거절합니다. 계좌 조회·재구성 쿼리는 항상 시장과 호출자 소유자 조건을 포함합니다.

DB는 로컬 디스크에 둡니다. 연결 함수는 UNC와 파일 URI를 거절하지만 마운트된 네트워크 파일시스템까지 판별하지 않습니다. 운영 환경의 디스크 위치와 단일 작성자 소유권 확인은 후속 운영 검증에 포함합니다.

원장 합계는 BigInt와 정확한 분수로 복원합니다. 원자·수량 문자열이나 양측 합계가 손상되면 복원을 실패시키며 금융 작업을 계속하지 않습니다. 이 단계의 단일 Repository는 동기적 트랜잭션 기반이며, 운영 단일 작성자 프로세스 잠금·Gateway 작업 분리·Outbox·전체 복구 검증은 후속 마일스톤의 완료 조건입니다.

## 개인정보 처리 범위

| 항목 | 현재 입력과 목적 | 저장 위치·보유 | 외부 전송 |
|---|---|---|---|
| Discord 사용자 ID | 테스트용 합성 문자열. 시장별 계좌 식별·중복 초기금 차단·소유자 조건 검증 | 테스트 임시 SQLite의 `accounts`, `processed_commands`; 테스트 종료 시 임시 디렉터리 삭제 | 없음 |
| Discord 서버·Interaction ID | 테스트용 합성 문자열. 시장 구분·요청 멱등성 | 동일 임시 DB; 테스트 종료 시 삭제 | 없음 |
| 모의 계좌·원장 | 합성 계좌의 잔고·수량·원가 복원 | 원장에는 내부 계좌 ID로 연결; 동일 임시 DB 삭제 | 없음 |

실사용자 연결은 이 단계에 없습니다. 단계 1의 공개 계좌 개설 전에 운영 보유기간·처리 안내·권리 행사·식별자 삭제와 초기금 중복 방지의 관계를 확정합니다. 현재 계좌 키 변경·삭제를 막는 제약은 금융 초기화 검증용이며, 운영 삭제 요청을 처리하는 기능이 아닙니다. 운영에서는 사용자 식별 연결의 파기와 비식별 금융 이력 보존을 함께 설계하고 해당 마이그레이션을 검증해야 합니다. 실명·이메일·전화·생년월일·주소·프로필 사진을 저장하는 필드는 추가하지 않았습니다.
