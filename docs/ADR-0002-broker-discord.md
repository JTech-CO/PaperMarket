# ADR-0002: 시험 시세의 계좌·시스템 체결과 Discord 경계

상태: 구현 · 날짜: 2026-10-03 · 적용: 백서 단계 1

## 시험 시세와 시간

8개 초기 종목을 1,000포인트로 유지하는 `STATIC_TRIAL` 공급자를 사용하고 시장 화면에 시험 시세임을 밝힙니다. 300초 경계마다 틱·공개 버전·순서를 원자적으로 갱신합니다. 기업 경제와 가격 변동은 단계 2 책임이며 사용자 수·주문량은 가격을 바꾸지 않습니다.

단일 Worker 메시지 순서와 서버 수신시각이 처리 순서를 정합니다. 경계 뒤 접수뿐 아니라 처리 시각이 경계를 지난 견적도 이전 버전에서 체결하지 않습니다. 매초 남은 활성시간을 체크포인트하고 시작 시 남은 구간을 재배치하여 오프라인 시간을 제외합니다. 체크포인트 뒤 장애까지의 짧은 미기록 구간은 소급 적용하지 않습니다.

## 견적·체결·저장

견적은 난수 토큰 32바이트, 계좌·서버 범위 소유자 HMAC·종목·방향·수량·가격·시장/계좌 버전·30초 만료에 연결합니다. 자산 예약은 없으며 확인 때 소유자·만료·현재 버전·현금·보유량을 다시 검사합니다. 버전 변화는 거절하고 새 견적과 명시적 확인을 요구합니다.

유효 주문은 다른 참가자 없이 시스템이 전량 체결합니다. 예산은 양방향 0.1% 수수료를 포함하고 소수점 6자리 수량 중 최대값을 계산합니다. 매수 수수료는 취득원가에 포함하고 매도 때 평균 원가를 제거합니다. 원가 원자 배분의 잔돈은 남은 보유분에 두며 마지막 전량 매도가 잔여 원가를 모두 제거합니다. 현재 보유분은 사용자 수량으로 생성되며 더 정밀한 기업행동 권리 수량은 단계 3에서 연결합니다.

주문·체결·현금 전표·수량/원가 전표·계좌 버전·시장 순서를 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 커밋합니다. 의도당 체결 유일성으로 다른 Interaction의 중복 버튼도 기존 체결을 반환합니다. 캐시 금융 명령 응답은 형태·소유자·기존 의도/체결·원장과 대조하며 무결성 실패는 시장을 정지합니다. 조회는 현재 본인 원장을 투영하고 응답 캐시를 남기지 않습니다.

마이그레이션 2는 단계 0 SQL·체크섬·원장·계좌·초기금을 보존합니다. 계좌 키·원장·주문·체결·견적 핵심 조건은 불변 제약으로 보호합니다.

## Discord와 실행

Gateway는 인증된 Interaction에서 서버·사용자·권한·수신시각을 결정하고 비공개 defer 성공 후 백엔드를 실행합니다. 영속 custom ID 경로를 사용하고 버튼 토큰이 소유자 권한을 대체하지 않습니다. SQLite·금융 계산은 전용 Worker로 격리합니다.

프로세스 잠금·소유 nonce·죽은 PID 재확인으로 동일 DB의 단일 작성자를 유지합니다. 잠금 복구도 획득 가드로 직렬화하고 손상된 파일은 자동으로 빼앗지 않습니다. Worker 시작 10초·종료 5초 제한과 비정상 종료의 Gateway 정리·실패 종료를 연결합니다.

현황판 전달은 금융 커밋과 분리하고 변경된 시장 버전만 전달합니다. 대기 스냅샷은 시장별 최신값으로 합치며 API 실패가 원장을 되돌리거나 재체결하지 않습니다. 공개 메시지 생성·복구는 서버별 비동기 큐로 직렬화합니다. 같은 설정 Interaction 재전달은 최신 저장 참조를 읽고 설정 채널이 달라졌으면 충돌로 거절합니다. 채널 이동은 새 참조 저장 후 이전 게시물을 이동 안내로 수정합니다.

## 보안·개인정보

모든 입력을 서버에서 검증하고 SQL을 바인딩합니다. 조회·변경에 서버·계좌·소유자 ID/HMAC 조건을 적용합니다. 공개 현황판은 시장 필드만 허용하고 개인 응답은 비공개이며 멘션을 차단합니다. 자격증명·원본 예외는 응답·진단에 넣지 않습니다. 단기 burst·대기 보호는 일일 매매 제한과 분리합니다.

실제 운영 주체·지원 연락처 없이는 시작하지 않습니다. 연령 자기 확인·약관 동의를 각각 받고 생년월일·채팅·회원 목록은 수집하지 않습니다. `/close`는 원래 Discord ID·개설 확인·개인 캐시·대기 토큰을 정리합니다. 서버 범위 HMAC·계좌 매핑·금융원장은 시장 존속기간 보관하여 재개설·최초금 재지급을 막습니다. 가명정보이며 전체 삭제·익명화를 뜻하지 않습니다. 활성 레코드 제거와 WAL·백업의 복구 불가능한 파기는 구분합니다. 실제 운영 확인 사항은 [정책 문서](policy/README.md)에 기록합니다.

## 검증 범위

숫자·저장·브로커·모의 Discord·실제 Worker 검사와 독립 검토를 수행했습니다. 임시 DB의 9.99주 왕복 매매는 양측 수수료 후 현금 9,980.02·보유 0·체결 2건이며 중복 확인·재시작 뒤에도 같습니다. 커밋 전 실패는 롤백하고 커밋 후 응답 실패는 금융 작업을 반복하지 않습니다.

실제 Discord 연결·명령 등록·장시간 Gateway·부하 목표·경제 모형·운영 백업·공개 개인정보 운영 검증은 수행하지 않았습니다. 정책 문서는 현재 시험 구현을 설명하는 초안입니다.
