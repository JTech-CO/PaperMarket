# 단계 6 개인정보 흐름과 운영 확인 사항

기준 버전은 `trial-v6`, 개발 안내 기준일은 2026-10-09입니다. 합성 데이터 개발 검증과 실제 운영 확인을 구분합니다. 이전 v1·v2·v3·v4·v5 약관·처리 안내 원본은 `versions`에 보관합니다. 단계 5의 성과·기준전략·관심종목·가격 조건·비공개 알림함·선택 DM 동의/발송·본인 내보내기에 단계 6의 로컬 암호화 백업·복구 도구를 추가합니다. 단계 6의 최종 검증은 진행 중이며 공개 운영 승인이나 권리 행사 검토 완료를 의미하지 않습니다. 신규 연락처·프로필·추적 정보를 수집하지 않습니다. 이벤트는 합성 가상 기업의 경제 콘텐츠이며 사용자 메시지나 실제 뉴스를 수집하는 기능이 아닙니다.

이번 검증은 내부 단위·저장 통합 테스트, 모의 Discord Interaction과 로컬 차트/화면 자료를 대상으로 합니다. 실제 Discord 연결·명령 등록·첨부/DM 외부 전송·실기기 모바일/테마·운영자 권리 요청 응대·공개 운영은 검증하지 않았습니다. 계좌 종료의 ID 제거는 활성 SQLite 레코드 기준이며, SQLite 파일의 이전 페이지·WAL·운영 백업까지 복구 불가능하게 파기했다는 뜻은 아닙니다. 알림 외부 발송은 중복 가능성을 가진 재시도 방식이며 금융 작업의 멱등성과 구분합니다.

실행 중 `/help`, `/privacy`, 계좌 종료 안내에는 서버 환경설정의 실제 운영 주체와 지원 연락처를 넣습니다. 저장소의 예제 연락처를 운영 연락처로 사용하면 안 됩니다. `validatePolicyOperator`는 운영 주체를 80자, 연락처를 254자로 제한하며 Discord 멘션·Markdown·제어문자와 HTTP·스크립트 URL을 받지 않습니다. 연락처는 이메일 또는 HTTPS 주소입니다.

## 개설과 종료 경계

- `/help`와 `/privacy`는 계좌 개설 전에 읽을 수 있습니다. 개인정보 처리 안내를 이용약관 안에만 넣지 않습니다.
- `/open`은 `age14Plus`와 `agreeTerms`가 각각 boolean `true`인 경우만 받습니다. 문서 버전·확인 시각은 서버에서 주입하며 클라이언트가 지정하지 않습니다. 마케팅과 포괄적인 개인정보 필수 동의 항목은 없습니다. 계좌 제공에 필요한 정보를 계약 이행 근거로 처리하는 설계입니다.
- `/close`의 확인값이 꺼져 있으면 종료 전 안내만 제공합니다. 켠 경우 인증된 Discord 사용자의 본인 계좌만 닫습니다. 현재 Discord 인증된 명령을 이용하며 별도 Discord 재로그인을 강제하는 재인증 기능은 제공하지 않습니다.
- 종료 시 미체결 조건주문을 취소하고 예약 자산을 해제합니다. 원래 Discord 사용자 ID, 개설 확인 기록·원본 확인 nonce·개인 캐시·관심종목·가격 알림·DM 설정·알림함·발송 작업·알림 중복 키·내보내기 접근 기록을 제거·무효화합니다. 접수된 조건주문·예약/해제·체결·성과·기준전략의 추가형 기록은 내부 계좌·가명 HMAC 연결로 보존합니다. 재개설·최초자금 재지급은 금지되며 이를 익명화 또는 전체 삭제라고 설명하지 않습니다.
- `/portfolio`, `/history`, `/orders`, `/performance`, `/alerts`가 본인 자료 조회 경로이며 `/export`는 본인 CSV/JSON 첨부를 제공합니다. 조회·설정·취소·페이지 기준에도 인증된 소유자 조건을 적용하고 타인 ID를 받는 명령 옵션은 없습니다. 정정·전체 삭제·처리정지·대리인 요청은 `/privacy`의 실제 지원 접수처로 시작할 수 있어야 합니다. 운영자는 본인 확인 방법·처리 대장을 마련하고 처리 결과와 제한 사유를 안내해야 합니다.

## 선택 DM과 발송 경계

DM은 개설 시 선택에 포함하지 않고 기본 꺼짐입니다. `/alerts dm:true`는 사용자 ID·확정 알림 내용의 Discord 전송 목적을 표시한 별도 동의이며 서버가 `dm-trial-v1`·동의 시각을 기록합니다. `/alerts dm:false`로 철회해도 계좌·거래·비공개 알림함을 계속 사용할 수 있습니다. 이미 보낸 메시지는 회수하지 않습니다.

알림·발송 작업을 확정 금융 트랜잭션 안에서 생성하고 커밋 이후 별도로 발송합니다. 작업은 최대 8회, 30초 임대로 재시도하며 전송 직전에 활성 계좌·동의·임대를 다시 확인합니다. 재시도 실패/만료나 Discord 수신 차단이 금융 커밋을 되돌리거나 체결을 다시 실행하지 않습니다. 원래 Interaction 토큰을 영속 보관하거나 지연 발송에 재사용하지 않습니다. 발송 후 확인 전 중단 같은 경우 외부 메시지가 중복될 수 있으며 정확히 한 번 전달을 보장하지 않습니다.

| 운영 주체·개인정보 담당·접수처 | 실제 값 없으면 Discord 시작 설정을 거절 | 실제 담당 성명 또는 부서명과 응답 가능한 연락처 |

| Discord 전송·플랫폼 처리 | 계좌 응답·명령을 Discord API/Gateway로 전달 | 국외 처리 국가·수신자 연락처·목적·보관기간·이전 근거·거부 절차를 실제 플랫폼 계약과 정책 기준으로 검토 |
| 시장 존속기간 | 가명 무결성 기록·금융원장이 남음 | 시험 종료일 또는 시장 종료 기준, 전체 DB·WAL·백업의 종료 파기 절차 |
| 백업·운영 로그 | 1시간 암호화 백업·기본 24/7/4 대표 사본·설정 시 일별 별도 경로 복제·30일 리허설, 운영 코드/집계 출력 | 실제 별도 장치·파일 권한·Windows ACL·키 복구 사본·실패 점검·로그 보관·전체 종료 파기, 복구 후 종료/철회 요청 수동 재반영 |
| 요청 처리 | 실제 지원 연락처가 공개 안내에 포함 | 접수·본인 확인·처리 결과 회신, 요청 처리 대장·일정·거절 사유 |
| 정책 개정 | 약관·처리 안내 버전은 서버 상수 | 적용 전 공지·이전 버전 제공·처리 범위 변경 시 필요한 별도 동의 판단 |

여기서 `시장 존속기간`은 무기한 개인 계좌 보관의 근거가 아닙니다. 종료 기준·전면 파기가 확정되지 않은 시험 DB를 실제 운영 개인정보 저장소로 장기 사용하지 않습니다. 현재 코드가 개별 계좌의 원장·금융 무결성 기록을 삭제한다고 약속하지 않습니다. 개인정보 처리 근거와 필요한 안전조치는 운영 사실을 포함해 단계 6에서 다시 검증합니다.

## 백업·복구와 종료 요청

백업은 스냅샷을 읽기 전용으로 검증하고 독립 `BACKUP_KEY`로 암호화한 뒤 인증된 manifest와 게시합니다. 기본 보관은 최근 24개, 최근 7개 UTC 날짜, 최근 4개 UTC 주간 구간의 대표 사본의 합집합입니다. 성공한 새 사본이 생기는 주기 점검에서 정리하므로 장애 중에도 정해진 날짜에 전부 지워진다고 보장하지 않습니다. 복제는 운영자가 명시한 절대 로컬 경로에만 수행하며 실제 다른 디스크·지역·외부 서비스 연결은 검증하지 않았습니다. Windows 파일 모드는 장비 ACL·접근 통제를 대신하지 않습니다.

이전 사본은 `/close`·DM 철회 전에 저장된 원래 식별자·동의·알림을 포함할 수 있습니다. 개별 요청 시 모든 과거 사본을 다시 쓰거나 즉시 소거하는 기능은 없습니다. 복구 전에 별도로 관리한 권리 요청 처리 결과를 대조하여 종료·철회를 다시 반영해야 하며, 별도 삭제 등록부의 자동 병합은 구현하지 않았습니다. 검증된 새 DB 파일만 만드는 도구를 계좌 재개설이나 최초자금 재지급 경로로 사용하지 않습니다. [운영·복구 절차](../OPERATIONS.md)의 중단·검증·새 경로 전환·권리 요청 재반영 순서를 따릅니다. 이 수동 절차와 지원 창구의 실제 수행 여부는 공개 운영 전에 확인해야 합니다.

## 확인한 법령 출처와 해석 범위

계약 체결·이행에 필요한 정보 처리 근거와 국외 처리의 공개·고지 요구는 2026-10-09에 [국가법령정보센터 개인정보 보호법 제15조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335387), [제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334957)의 제공 조문으로 확인했습니다. 이는 현재 설계의 검토 근거이며 Discord 계약이나 선택 DM 동의가 국외 처리 요건을 모두 충족한다는 판정은 아닙니다. 공개 전 최신 법령·플랫폼 사실과 적용 근거를 다시 확인해야 합니다. 문서는 법률 자문이 아니며 실사용자 데이터나 결제를 받기 전 전문가 검토가 필요합니다.
