# PaperMarket 개인정보 처리 안내 초안

버전: `privacy-trial-v3` / 작성일: 2026-10-04. 운영 주체·적용일·외부 플랫폼 처리 사실은 공개 전 확정합니다. `/privacy`는 계좌 없이 볼 수 있고 실제 운영 주체·접수처를 표시합니다. [이전 v2](versions/PRIVACY_TRIAL_V2.md)와 v1을 보관합니다. 이 문서는 법률 자문이 아닌 개발용 초안이며 실제 공개 전 전문가 검토가 필요합니다.

## 1. 항목과 목적

| 항목 | 목적 |
|---|---|
| Discord 사용자·서버 ID, 설정 채널·현황판 메시지 ID | 본인 계좌·서버별 시장 식별과 운영 |
| Interaction ID, 처리 시각·명령 결과 | 중복 처리 방지·확인·복구 |
| 계좌 ID·상태, 가상 현금·보유량·주문·체결·원장 | 모의자산 제공·양측 정산·정확한 재구성 |
| 현금 이자 발생 구간·분수 잔액·지급 기록 | 활성 보유시간 이자와 원자 미만 잔액을 정확히 복원 |
| 배당·청산 권리의 수량·명목·평가·지급·취득원가·분수 잔액 | 권리 확정·손상·지급·최종 손익과 시스템 대응 원장을 정확히 복원 |
| 만 14세 이상 자기 확인·약관 동의·문서 버전·확인 시각 | 개설 요건과 약관 수락 기록 |
| 서버 범위 HMAC 사용자 연결값·내부 계좌 매핑 | 계좌 연결과 최초자금 재지급 방지 |
| 일회성 주문 확인 토큰 | 본인 주문 확인·취소 |

생년월일, 실명, 이메일, 전화, 주소, 사진, 채팅 내용, 실제 금융계좌·결제정보, 주민등록번호를 봇의 계좌 개설·매매 명령으로 받지 않습니다. 운영자에게 별도로 문의를 보내는 경우 문의에 포함한 정보는 해당 접수 도구와 운영자의 문의 처리 절차를 따릅니다. 과도한 추가 개인정보를 문의로 요구하지 않습니다.

계좌 제공에 필요한 정보는 계좌 이용계약 체결·이행을 위한 처리로 설계합니다. 약관 수락과 개인정보 처리 고지를 구분하며 마케팅이나 포괄적인 개인정보 필수 동의 항목을 두지 않습니다. 다른 목적으로 사용하거나 수집 범위를 바꾸려면 처리 근거와 필요한 별도 고지·동의를 다시 검토해야 합니다.

## 2. 저장과 보유·종료

SQLite 파일은 실행 장비에 저장합니다. 코드에 외부 DB·분석·LLM·광고 서비스를 붙이지 않았습니다. 파일의 물리적 위치와 운영 접근 권한은 배포 책임자가 확정해야 합니다.

식별자와 약관 확인은 계좌 이용 중 보관합니다. `/close`에서 안내를 읽고 명시적으로 확인하면 원래 Discord 사용자 ID·개설 확인 기록을 제거하고 대기 주문 확인정보를 제거·무효화하여 본인 계좌 이용을 영구 종료합니다. 종료 계좌는 다시 열 수 없으며 최초자금을 재지급하지 않습니다.

금융원장·내부 계좌 ID·서버 범위 HMAC 연결값은 시장 존속기간 동안 금융 무결성 및 재지급 방지에 한정하여 남습니다. 이 연결값은 재식별 가능한 가명정보이며 익명정보가 아닙니다. 계좌 종료를 모든 기록의 전체 삭제라고 안내하지 않습니다. 시장 전체 종료 기준과 DB·WAL·백업의 파기 방법·보관주기는 실제 공개 전에 확정해야 합니다. 법정 5년 또는 90일 자동 파기가 구현되었다고 약속하지 않습니다.

배당·청산 권리 원장도 동일한 보관 경계를 따릅니다. 종료 계좌의 기존 보유와 권리는 틱 경계에서 무결성 정산을 계속 기록하지만 계좌를 다시 사용하거나 최초자금을 재지급하지 않습니다. 권리 원장에 신규 연락처·프로필·실제 금융정보를 추가하지 않습니다.

현실의 상품·서비스 결제가 없으므로 이 모의 원장을 실제 대금결제·배송 기록으로 보고 전자상거래 보존기간을 일괄 적용하지 않습니다. 실제 운영 형태에서 별도의 법령 보존 대상이 발생하면 항목·목적·기간을 검토하고 구분 보관해야 합니다.

## 3. 외부 플랫폼·위탁·국외 처리

Discord Gateway는 인증된 명령 정보를 전달하며 Discord API는 요청자만 보는 개인 계좌·주문·체결 응답과 공개 시장 현황판을 전달합니다. 봇은 사용자 프로필 이름·사진이나 채팅 내용을 추가 저장하지 않습니다. 비공개 응답도 Discord 외부 플랫폼에 전달되는 정보입니다.

Discord의 자체 정보 처리는 해당 플랫폼 정책과 계약을 함께 확인해야 합니다. `[[확인 필요: 실제 계약 주체·수신자 연락처·이전 국가·시기·방법·목적·보유기간·적절한 이전 근거·거부 방법과 효과]]`. 개발 코드만으로 플랫폼의 보관·삭제나 국외 처리 요건을 충족한다고 판정하지 않습니다. Discord 전송이 필요하므로 이를 거부하면 봇 계좌 응답 기능을 이용할 수 없으며 접수처를 통해 종료·권리 행사를 시작할 수 있습니다.

개발 코드에서 추가 광고·분석업체·LLM·외부 DB·결제업체에 보내는 제3자 제공·처리 위탁은 해당 없음입니다. 호스팅·문의·백업 서비스가 실제 운영에 추가되면 그 흐름과 필요한 사항을 별도로 고지해야 합니다.

## 4. 권리와 연령

`/portfolio`는 본인 모의자산, `/history`는 최근 체결을 조회합니다. `/close`는 본인 계좌 이용 종료를 시작하는 경로입니다. 원장 전체의 열람·정정·삭제·처리정지·내보내기는 실제 지원 접수처로 요청할 수 있습니다. 운영자는 필요 최소한으로 본인을 확인하고 처리 결과·처리 일정과 제한 사유를 안내해야 합니다. 계좌 연결과 금액·수량을 임의 정정하여 원장 무결성을 깨는 방식은 사용하지 않습니다.

종료 확인은 인증된 Discord Interaction과 본인 계좌 조건에 의존하며 별도 Discord 재로그인을 강제하지 않습니다. Discord 계정 탈취가 의심되면 먼저 계정 접근을 보호하고 운영 접수처에 알려야 합니다.

만 14세 미만 계좌 개설을 받지 않습니다. 이용자는 만 14세 이상임을 직접 확인하며 생년월일·신분증은 받지 않습니다. 이 절차가 실제 연령 검증을 완료한다는 의미는 아닙니다. 아동 정보가 처리되었다는 사실이 확인되면 운영자가 해당 요청과 파기를 별도로 처리해야 합니다. 법정대리인·대리인의 권리 요구는 접수처에서 처리 방법을 안내해야 합니다.

## 5. 안전조치와 자동 처리

코드는 인증된 Discord 사용자 문맥을 이용하고 소유자 조건으로 개인 계좌·주문을 다룹니다. 입력 범위, 명령 제한, 안전한 일회성 확인 토큰, 거래 멱등성, 추가형 원장·양측 균형 검증을 적용합니다. 개인 정보 응답은 비공개이며 공개 현황판에는 계좌·개인 거래를 표시하지 않습니다. 요청 payload·토큰·사용자 프로필을 운영 로그로 출력하지 않습니다.

SQLite 저장 파일·백업의 디스크 암호화·담당자 접근 통제·접근기록·복구 후 종료된 계좌 보호·사고 대응은 운영 장비에서 확정하고 검증해야 합니다. 코드가 저장 파일 전체를 암호화하거나 모든 운영자 접근을 자동 기록한다고 약속하지 않습니다.

가상 기업의 공개 실적·전망·금리로 모의 시세를 계산하고 주문·체결·잔액·보유시간별 예치이자를 자동 계산합니다. 속도·소유자·자산 조건으로 요청을 제한합니다. 현실의 신용·보험·채용 심사나 현실의 투자 추천은 제공하지 않습니다. 계산 결과·제한의 사유 설명은 접수처로 요청할 수 있습니다.

## 6. 쿠키·마케팅·문의·개정

웹 쿠키·광고 추적·마케팅 수신·추가 프로필은 해당 없음입니다. Discord 클라이언트가 사용하는 쿠키 등 자체 장치는 해당 플랫폼 정책에 따릅니다.

- 운영 주체·개인정보 문의 담당: `[[확인 필요: 실제 성명 또는 부서명]]`
- 지원 접수처: `[[확인 필요: 실제 응답 가능한 이메일 또는 HTTPS 주소]]`
- 실제 시행일·시험 종료 기준: `[[확인 필요: 운영 일정]]`

운영자는 수집·목적·외부 처리·보관 사항 변경을 적용 전에 알리고 이전 버전을 보관해야 합니다. 필요한 별도 동의가 있는 변경인지 다시 판단합니다. [개인정보 흐름 지도와 운영 확인 사항](README.md)을 함께 유지합니다.
