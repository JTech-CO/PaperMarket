# PaperMarket 개인정보 처리 안내 초안

버전: `privacy-trial-v6` / 개발 안내 기준일: 2026-10-09. 운영 주체·실제 적용일·외부 플랫폼 처리 사실은 공개 전 확정합니다. `/privacy`는 계좌 없이 볼 수 있고 실제 운영 주체·접수처를 표시합니다. [이전 v5](versions/PRIVACY_TRIAL_V5.md)와 v4·v3·v2·v1 원본을 보관합니다. 단계 6의 최종 검증은 진행 중이며 실제 권리 행사·공개 운영·법률 검토 완료를 의미하지 않습니다. 이 문서는 법률 자문이 아닌 개발용 초안이며 실사용자 데이터나 결제를 받기 전 운영 사실을 확정하고 전문가 검토를 받아야 합니다.

계좌 제공에 필요한 정보는 계좌 이용계약 체결·이행을 위한 처리로 설계합니다. 약관 수락과 개인정보 처리 고지를 구분하며 마케팅이나 포괄적인 개인정보 필수 동의 항목을 두지 않습니다. 다른 목적으로 사용하거나 수집 범위를 바꾸려면 처리 근거와 필요한 별도 고지·동의를 다시 검토해야 합니다.

DM 전달은 기본 꺼짐의 별도 선택입니다. `/alerts`에서 명시적으로 켤 때 사용자 ID·확정 알림 내용의 Discord 전달 목적과 동의 시각·버전을 기록합니다. 거부해도 계좌·거래·비공개 알림함을 이용할 수 있고 같은 설정에서 끄면 즉시 대기 작업을 취소합니다. 이미 전달한 DM을 자동으로 회수하지는 않습니다. 이 선택을 광고·마케팅 동의나 Discord 국외 처리의 법적 근거가 모두 확정되었다는 의미로 사용하지 않습니다.

## 2. 저장과 보유·종료

SQLite 파일은 실행 장비에 저장합니다. 코드에 외부 DB·분석·LLM·광고 서비스를 붙이지 않았습니다. 파일의 물리적 위치와 운영 접근 권한은 배포 책임자가 확정해야 합니다.

식별자와 약관 확인은 계좌 이용 중 보관합니다. 관심종목·가격 조건은 각각 최대 20개이며 삭제 명령 또는 계좌 종료까지 보관합니다. 종목 소멸 때 조건을 비활성화하고 새 회사에 승계하지 않습니다. 알림함은 계좌당 최근 1,000건을 유지하고 새 기록을 추가할 때 오래된 항목과 연결된 발송 작업을 제거합니다. 알림 중복 방지 키는 오래된 알림을 지운 뒤 재생해도 같은 사건을 다시 만들지 않도록 계좌 종료까지 보관합니다. DM 설정·동의 시각·버전·발송 상태는 계좌 이용 중 보관합니다. 동의 철회 시 현재 동의 시각을 제거하고 대기 발송을 취소합니다.

내보내기 접근 기록은 계좌당 최근 1,000건을 계좌 이용 중 보관하고 계좌 종료 시 제거합니다. 원본 Discord ID·Interaction 토큰·파일 내용은 접근 기록에 저장하지 않습니다.

`/close`를 명시적으로 확인하면 미체결 조건주문을 취소하고 예약 자산을 해제합니다. 원래 Discord 사용자 ID·개설 확인 기록·원본 확인 nonce·개인 캐시·관심종목·가격 조건·DM 설정·알림함·연결 발송 작업·중복 방지 키·내보내기 접근 기록은 제거·무효화하여 계좌 이용을 영구 종료합니다. 계좌는 다시 열 수 없고 최초자금을 재지급하지 않습니다. 접수된 조건주문과 예약/해제·체결의 금융 이력은 불변 원장과 함께 가명 연결로 남습니다.

금융원장·성과 표본·기준전략 스냅샷·내부 계좌 ID·서버 범위 HMAC 연결값은 시장 존속기간 동안 금융 무결성·결과 추적·재지급 방지에 한정하여 남습니다. 이 연결값은 재식별 가능한 가명정보이며 익명정보가 아닙니다. 계좌 종료를 모든 기록의 전체 삭제라고 안내하지 않습니다. 시장 전체 종료 기준과 DB·WAL·보관 백업의 최종 파기 방법은 실제 공개 전에 확정해야 합니다. 법정 5년 또는 90일 자동 파기가 구현되었다고 약속하지 않습니다.

단계 6은 SQLite Online Backup으로 만든 스냅샷을 검증한 뒤 독립 서버 키 `BACKUP_KEY`로 AES-256-GCM 암호화하고 인증된 manifest와 로컬 보관합니다. 기본 정책은 1시간 백업, 최근 24개·최근 7개 UTC 날짜·최근 4개 UTC 주간 구간의 대표 사본의 합집합 보관, 운영자가 명시한 별도 절대 경로로 일별 복제, 30일 리허설입니다. 성공 주기 점검에서 정책상 사본을 정리하며 실패·중단 중에도 특정 날짜에 전부 소거한다고 약속하지 않습니다. 다른 폴더가 실제 별도 장치나 지역인지는 운영자가 확인해야 합니다. 외부 백업 서비스는 연결하지 않았습니다.

백업에는 생성 시점의 개인 식별자·동의·알림이 들어갈 수 있습니다. 계좌 종료·DM 철회가 이전 사본을 즉시 다시 쓰거나 지우지는 않습니다. 오래된 사본을 복구하면 종료 전 정보가 돌아올 수 있으므로 운영자가 별도로 관리한 권리 요청 처리 결과를 수동 대조하여 종료·철회를 재반영한 뒤 운영을 재개해야 합니다. 삭제 등록부의 자동 병합은 구현하지 않았습니다. [운영 절차](../OPERATIONS.md)의 기록 프로세스 중단·새 DB 파일 복구·권리 요청 대조를 따릅니다. 복구 도구가 원본 DB/WAL을 덮어쓰거나 종료 계좌를 재개설하지 않습니다.

검증용 평문은 제한된 임시 디렉터리에 생성하여 정상/오류 처리 후 제거합니다. 강제 중단 후에는 다음 유지보수 잠금 아래 인증된 소유 작업의 정확한 경로·파일명을 확인해 정리합니다. 확인 불가한 고아 파일과 Windows ACL·원본 SQLite/WAL·키 복구 사본·저장장치 권한은 운영자가 관리해야 합니다. 암호화된 사본을 보관한다는 사실이 전체 디스크의 복구 불가능한 파기나 모든 운영자 접근 기록을 보장하지 않습니다.

배당·청산 권리 원장도 동일한 보관 경계를 따릅니다. 종료 계좌의 기존 보유와 권리는 틱 경계에서 무결성 정산을 계속 기록하지만 계좌를 다시 사용하거나 최초자금을 재지급하지 않습니다. 권리 원장에 신규 연락처·프로필·실제 금융정보를 추가하지 않습니다.

현실의 상품·서비스 결제가 없으므로 이 모의 원장을 실제 대금결제·배송 기록으로 보고 전자상거래 보존기간을 일괄 적용하지 않습니다. 실제 운영 형태에서 별도의 법령 보존 대상이 발생하면 항목·목적·기간을 검토하고 구분 보관해야 합니다.

## 3. 외부 플랫폼·위탁·국외 처리

Discord Gateway는 인증된 명령 정보를 전달하며 Discord API는 요청자만 보는 개인 계좌·주문·체결·성과·알림함 응답과 CSV/JSON 내보내기 첨부, 선택한 개인 DM, 공개 시장 현황판을 전달합니다. 봇은 사용자 프로필 이름·사진이나 채팅 내용을 추가 저장하지 않습니다. 비공개 응답·첨부·DM도 Discord 외부 플랫폼에 전달되는 정보입니다. 전송 직전에 활성 계좌와 DM 동의·발송 임대를 다시 확인하며 원래 Interaction 토큰으로 지연 알림을 보내지 않습니다.

내보내기 파일은 메모리에서 생성하고 봇 디스크에는 저장하지 않습니다. 내려받은 개인 사본과 Discord가 전달·보관한 첨부·DM의 삭제는 로컬 계좌 종료와 별도이며 봇이 플랫폼 보관 기한이나 복구 불가능한 삭제를 보장하지 않습니다.

Discord의 자체 정보 처리는 해당 플랫폼 정책과 계약을 함께 확인해야 합니다. `[[확인 필요: 실제 계약 주체·수신자 연락처·이전 국가·시기·방법·목적·보유기간·적절한 이전 근거·거부 방법과 효과]]`. 개발 코드만으로 플랫폼의 보관·삭제나 국외 처리 요건을 충족한다고 판정하지 않습니다. Discord 전송이 필요하므로 이를 거부하면 봇 계좌 응답 기능을 이용할 수 없으며 접수처를 통해 종료·권리 행사를 시작할 수 있습니다.

개발 코드에서 추가 광고·분석업체·LLM·외부 DB·결제업체에 보내는 제3자 제공·처리 위탁은 해당 없음입니다. 호스팅·문의·백업 서비스가 실제 운영에 추가되면 그 흐름과 필요한 사항을 별도로 고지해야 합니다.

## 4. 권리와 연령

`/portfolio`는 본인 모의자산과 가용/예약 자산, `/history`는 체결·배당·정정 이력, `/orders`는 본인 조건주문과 상태를 조회하고 취소합니다. `/performance`는 본인 성과·기준전략, `/alerts`는 본인 설정·알림함 조회와 DM 철회 경로입니다. `/export`는 본인 기록을 CSV/JSON 첨부로 제공합니다. 한 페이지의 이력은 최대 1,000개이고 다음 페이지 기준을 이어서 사용할 수 있습니다. 명시한 공개·본인 필드만 제공하고 타인 기록·미공개 경제 상태·운영 시드·확인 nonce·발송 임대 토큰을 제외합니다. CSV의 수식 실행 문자는 이스케이프합니다.

`/close`는 본인 계좌 이용 종료를 시작하는 경로입니다. 기타 열람·정정·전체 삭제·처리정지·대리인 요청은 실제 지원 접수처로 시작할 수 있습니다. 운영자는 필요 최소한으로 본인을 확인하고 처리 결과·처리 일정과 제한 사유를 안내해야 합니다. 계좌 연결과 금액·수량을 임의 정정하여 원장 무결성을 깨는 방식은 사용하지 않습니다.

종료 확인은 인증된 Discord Interaction과 본인 계좌 조건에 의존하며 별도 Discord 재로그인을 강제하지 않습니다. Discord 계정 탈취가 의심되면 먼저 계정 접근을 보호하고 운영 접수처에 알려야 합니다.

만 14세 미만 계좌 개설을 받지 않습니다. 이용자는 만 14세 이상임을 직접 확인하며 생년월일·신분증은 받지 않습니다. 이 절차가 실제 연령 검증을 완료한다는 의미는 아닙니다. 아동 정보가 처리되었다는 사실이 확인되면 운영자가 해당 요청과 파기를 별도로 처리해야 합니다. 법정대리인·대리인의 권리 요구는 접수처에서 처리 방법을 안내해야 합니다.

## 5. 안전조치와 자동 처리

코드는 인증된 Discord 사용자 문맥과 서버·계좌 소유자 조건으로 개인 계좌·주문·성과·알림·내보내기를 다룹니다. 입력 범위, 명령 제한, 안전한 일회성 확인 토큰, 거래 멱등성, 추가형 원장·양측 균형 검증을 적용합니다. 개인 정보 응답은 비공개이며 공개 현황판에는 계좌·개인 거래를 표시하지 않습니다. 요청 payload·토큰·사용자 프로필을 운영 로그로 출력하지 않습니다. 알림 생성은 금융 트랜잭션에 포함하고 Discord 전달은 커밋 이후 별도로 재시도하므로 발송 실패가 자산을 되돌리거나 체결을 재실행하지 않습니다.

백업 암호화·인증·읽기 전용 복구 지문 검사를 구현했습니다. 원본 SQLite/WAL의 디스크 암호화·Windows ACL·담당자 접근 통제·접근기록·복구 후 종료/철회 요청 수동 대조·사고 대응은 운영 장비에서 확정하고 검증해야 합니다. 코드가 저장 파일 전체를 암호화하거나 모든 운영자 접근을 자동 기록한다고 약속하지 않습니다.

가상 기업의 공개 실적·전망·금리·합성 사건으로 모의 시세를 계산하고 조건주문·예약·만료·체결·잔액·보유시간별 예치이자를 자동 계산합니다. 사건은 가상 기업 콘텐츠이며 실제 뉴스나 사용자 메시지를 수집하지 않습니다. 속도·소유자·자산 조건으로 요청을 제한합니다. 현실의 신용·보험·채용 심사나 현실의 투자 추천은 제공하지 않습니다. 계산 결과·제한의 사유 설명은 접수처로 요청할 수 있습니다.

## 6. 쿠키·마케팅·문의·개정

웹 쿠키·광고 추적·마케팅 수신·추가 프로필은 해당 없음입니다. Discord 클라이언트가 사용하는 쿠키 등 자체 장치는 해당 플랫폼 정책에 따릅니다.

- 운영 주체·개인정보 문의 담당: `[[확인 필요: 실제 성명 또는 부서명]]`
- 지원 접수처: `[[확인 필요: 실제 응답 가능한 이메일 또는 HTTPS 주소]]`
- 실제 시행일·시험 종료 기준: `[[확인 필요: 운영 일정]]`
