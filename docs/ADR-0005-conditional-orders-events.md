# ADR-0005: 조건주문·자산 예약·가상 사건

작성일: 2026-10-04. 단계 4 구현 기준은 백서 8·11·16·20절입니다. 기존 기업·가격·권리·현금 원장을 유지하며 다른 참가자가 없어도 주문을 접수하고 체결할 수 있습니다. 실제 뉴스·실제 증권 주문·현금 보상은 제공하지 않습니다.

## 견적과 확정

시장가 매수는 수량 또는 수수료 포함 예산, 시장가 매도는 수량 또는 가용 전량을 받습니다. 지정가 매수·매도와 스톱 매도는 수량과 조건가격을 받으며 예산·전량 옵션을 함께 사용하지 않습니다. 스톱 매수·스톱리밋·OCO·부분체결은 지원하지 않습니다.

견적은 사용자·시장·의도에 귀속된 최대 30초 확인 nonce와 확정 시장/계좌 버전을 사용합니다. 견적 단계에는 현금·수량을 예약하지 않습니다. 버전·소유자·기간·가용 자산을 확인한 뒤 같은 트랜잭션에서 확정합니다. 이미 조건을 충족한 지정가·스톱은 현재 확정 시세로 즉시 전량 체결하고, 충족하지 않은 조건주문은 자산을 예약한 OPEN 상태로 남습니다. 중복 확인은 새 주문을 만들지 않고 기존 체결 또는 접수 결과를 돌려줍니다.

조건 견적의 현재 시세는 참고값이며 예상 대금·수수료는 조건가격 기준입니다. 지정가 매수의 최대 예약금과 실제 확정가 정산을 구분합니다. 매수 조건은 현재가 ≤ 지정가, 지정가 매도는 현재가 ≥ 지정가, 스톱 매도는 현재가 ≤ 발동가격입니다. 모두 조건가격 대신 실제 확정 시세로 체결합니다. 스톱은 950→800 갭 하락에서 900 조건을 통과했다면 800에 체결될 수 있고 손실액을 보장하지 않습니다.

## 예약과 추가형 기록

지정가 매수는 `수량×조건가격+최대 수수료`를 예약하고 매도·스톱은 주식 수량을 예약합니다. 총 현금·보유량은 예약만으로 줄거나 늘지 않습니다. 가용 현금/수량은 총액에서 미체결 예약을 뺀 값이며 시장가·다른 조건주문도 같은 가용 자산 검사를 거칩니다. 유리한 가격에 체결한 뒤 남은 예약금은 해제합니다.

예약 현금은 총 현금의 일부로 예치이자를 얻습니다. 예약 주식도 실제 소유량이므로 배당 권리를 유지합니다. 같은 수량에 지정가 매도와 스톱을 중복 예약하는 방식은 허용하지 않습니다. 마이그레이션 5의 조건주문과 예약 전표를 추가형 상태 변경으로 재생하며 예약/해제의 시스템 반대편, 잔액·상태·해시를 검증합니다. 금융 원장과 예약 상태를 불일치하게 커밋하지 않습니다.

## 전체 시장 틱·만료·기업행동

기간은 `TICK_COUNT` 기본 21틱이며 1~10,000틱 또는 `UNTIL_CANCELLED`를 지원합니다. 만료는 전체 시장 틱으로 표기하며 기존 시험 시장에 경제를 도입한 경우의 별도 경제 틱과 혼동하지 않습니다. 정확히 만료 틱에서는 새 시세를 사용하기 전에 만료합니다.

경계 처리는 만료 → 기업행동에 따른 취소 → 새 시세 확정 → 조건 평가 순서입니다. 같은 계좌의 여러 조건이 충족되면 접수 순번으로 처리합니다. 배당락·교환·소멸 같은 기준가격/권리 변경은 해당 미체결 주문을 취소하고 예약을 해제합니다. 단순 배당 지급일은 취소 사유가 아닙니다. 새 회사에 옛 주문을 자동 이전하지 않습니다. 기업·공시·가격·배당·이자·주문 상태·예약 해제·실제 체결은 하나의 금융 틱 트랜잭션으로 커밋합니다.

## 사건 콘텐츠와 공개 경계

사건 카탈로그는 백서의 8개 기업별 24개=192개, 거시(MAC) 24개, 기업 관계(XCO) 24개로 총 240개 경제 템플릿을 사용합니다. 템플릿은 원인·프로필·변경 대상·기간·감쇠·적격 상태·후속 단계·공개 시차·출처·확실성·실제/예상/이전 값의 계약을 가집니다. 주가를 직접 몇 퍼센트 올리거나 내리는 지시는 허용하지 않습니다.

새 사건 후보와 프로젝트 후속 단계는 별도의 결정적 난수 문맥에서 선택합니다. 계좌 개설·조회·사용자 주문량은 사건 선택이나 기업/가격 상태를 바꾸지 않습니다. 계약은 협상·성사·매출 인식·현금 수금·해지 같은 단계를 연결하고, 설비·연구·마케팅 지출은 각 회계 성격을 유지합니다. 동일 프로젝트의 성공·실패나 같은 현금흐름을 중복 처리하지 않습니다.

신규 후보 수는 평균 0.35의 포아송 분포에서 틱당 최대 8개로 제한합니다. 정기 발표와 활성 프로젝트의 후속 처리는 이 예산과 별도로 진행합니다. 같은 프로젝트 원인으로 이미 실행한 템플릿은 추첨과 후속 후보에서 제외합니다. 표시 건수 제한은 저장된 사건·진행 중 효과를 삭제하지 않으며, 사건 이력의 저장 상한에 도달하면 무결성 오류로 중단합니다.

양측 설비 계약의 선급금 30%는 발주자의 건설중자산과 공급자의 계약부채로 대응하고 검수 후에 인식합니다. 취소·실패 시 환급하며 공급자 현금이 부족한 부분은 같은 원인의 발주자 채권·공급자 채무로 보존합니다. 검수 후 결함은 해당 고객 장비의 손상과 공급자의 보증 의무를 구분합니다. 연구권리 취득은 새 연구 인스턴스를 시작하며 검증 전 고객·매출을 늘리지 않습니다. RVI 시설 사고의 가동 제약은 뉴스 기간이 끝났다는 이유로 풀지 않고 실제 수리 검수 후 해제합니다.

미공개 발생 결과와 후속 프로젝트 파이프라인은 가격 입력·Discord 응답에 전달하지 않습니다. 공개 시차가 지나 확정 공시가 된 뒤 예상 대비 실제 차이와 수요·비용·신용위험 등을 공개 전망에 반영합니다. 계약금 전체를 현금이나 기업가치로 곧바로 더하지 않습니다. BELIEF는 공개된 시장 믿음과 감쇠를 통해 가격의 기대 경로에 반영하고 현금·기초 실적을 직접 바꾸지 않습니다. 거시 사건도 관측 가능한 지표와 정기 회의의 경계를 유지합니다.

기존 단계 2·3 스냅샷은 저장된 원문과 해시를 먼저 검증하고 메모리 기본값을 보완합니다. 사건 런타임·공개 사건 필드가 추가되었다는 이유로 과거 스냅샷이나 금융 이력을 다시 쓰지 않습니다. 현실의 사건 빈도·기업 성과를 재현했다는 판정은 장기 통계 검증과 구분합니다.

## Discord·소유권·개인정보

`/buy`·`/sell`의 `order_type`, `price`, `time_in_force`, `ticks`로 조건을 선택합니다. `/orders`는 미체결 우선 서버 최대 25건 중 최대 4건을 표시하고 같은 행에 취소 버튼을 둡니다. `/portfolio`는 총액과 가용/예약 자산을 분리합니다. 개인 명령과 영속 버튼은 비공개 선응답 이후 백엔드를 실행하며 소유자는 인증된 Gateway 사용자로만 결정합니다. 주문 ID를 위조해도 서버의 계좌/소유자 조건을 통과할 수 없습니다.

취소·만료·기업행동·계좌 종료는 예약을 해제하는 종료 전표로 남습니다. `/close`는 미체결 주문을 취소하고 원래 Discord ID·확인 nonce·개인 캐시를 제거/무효화합니다. 접수된 조건주문과 예약/해제 전표는 내부 계좌·HMAC 가명 연결로 시장 존속기간 보관하며 전체 삭제라고 설명하지 않습니다. 정책 v4에 추가 금융 기록과 이 경계를 고지하고 이전 v3 문서 원본을 보관합니다.

운영 시드·키·미공개 상태·nonce·SQL·예외는 공개 로그와 응답에 출력하지 않습니다. 멘션을 비활성화하고 표시 문자열을 이스케이프합니다. 동일 확인·취소의 응답 전송이 실패해도 금융 작업을 재실행하지 않습니다. 실제 Discord 연결·권리 요청 응대·장기 모형·부하·백업 파기는 별도 검증 범위입니다.
