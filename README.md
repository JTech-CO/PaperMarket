# PaperMarket

가상 기업의 실적·금리·현금흐름·공시와 시장 기대로 움직이는 Discord 모의투자 시뮬레이터입니다. 투자 판단과 그 결과를 기록하며, 혼자 이용할 수 있는 시스템 체결을 제공합니다. 실제 자금·주식과 연결되지 않습니다.

구현 기준은 [기술·디자인 백서](docs/PaperMarket_Technical_Whitepaper_KR.md)입니다.

초기 8종목은 1,000포인트에서 시작하고, 5분마다 기업 경제·금리·공개 실적과 전망으로 가격을 형성합니다. 배당 권리·손상·청산 회수·세대 교체와 조건주문 예약·해제를 원장에 기록합니다. 참가자가 없어도 시장은 진행하며 가입·조회·사용자 매매·알림 발송은 기업 경제와 가격·사건 경로를 바꾸지 않습니다.

## 개발 환경과 검증

Node.js **24.20.0**을 사용합니다. `.node-version`에 런타임을, `package-lock.json`에 패키지 버전을 고정합니다.

```powershell
node --version
npm ci --ignore-scripts
npm run check
npm run verify:foundation
npm run verify:broker
npm run verify:economy
npm run verify:actions
npm run verify:orders
npm run verify:events
npm run verify:recovery
npm run verify:load
npm run verify:model -- --preset pilot --max-ticks-per-run 1000 --max-seconds 60
```

`check`는 strict 형 검사와 숫자·원장·브로커·경제·권리·가격·조건주문·사건·기준전략·성과·알림·내보내기·PNG·모의 Discord Interaction·실제 SQLite Worker 테스트를 실행합니다. `verify:foundation`은 최초금과 원장 재개방을, `verify:broker`는 시험 시세의 왕복 매매·중복 확인·워커 재시작을 검증합니다. `verify:economy`는 실제 SQLite 시장 2개를 67틱 진행해 공시·가격·이자·참가자 독립을 대조합니다. `verify:actions`는 합성 고정 시나리오를 70틱 진행해 배당락·매도 후 권리·실지급·이전 견적 취소·오프라인 재시작을 검사합니다. `verify:orders`는 예약·조건 체결·만료·재시작을, `verify:events`는 사건 콘텐츠·공개 시차·재시작·오프라인 시간 제외를 대조합니다. 진단은 임시 DB만 사용하고 시드·토큰·개인 식별자를 출력하지 않습니다. SQLite 3.51.3 이상을 검사하며 마이그레이션 6은 기존 1~5와 경제 원문 해시를 유지하고 성과·기준전략·알림/발송·내보내기 접근 기록을 추가합니다.

단계 5의 로컬 화면 자료는 [artifacts/milestone5](artifacts/milestone5)에 18개 PNG로 보관합니다. 모바일 390px와 데스크톱·다크/라이트의 합성 Discord payload 미리보기이며 실제 Discord 클라이언트 화면 캡처가 아닙니다. 시장·배당락·퇴역 종목·성과·거래 중단·오래된 견적과 차트 자료를 포함합니다. 차트 4장은 1,000×480이며 현재 측정 파일 크기는 최대 37,283바이트입니다. 렌더러의 250,000바이트 상한과 달리 이 크기는 현재 고정 자료의 실측값입니다.

## 시험 서버에서 실행

1. `.env.example`을 `.env`로 복사하고 봇 토큰·Application ID·시험 서버 ID·실제 운영 주체·지원 연락처를 넣습니다. 지원 연락처는 이메일 또는 HTTPS 주소입니다. `ACCOUNT_IDENTITY_KEY`와 `MARKET_SEED`는 각각 32~64바이트의 안전한 난수를 hex로 생성합니다. 단계 6부터 독립적인 32바이트 암호화 키 `BACKUP_KEY`도 필수입니다. 보호된 키 복구 사본을 원본 장비와 구분해 보관합니다. 기존 DB의 키나 경제 시드를 바꾸거나 잃으면 시작을 거절합니다.
2. 봇을 `bot`·`applications.commands` 범위로 초대하고 기존 텍스트 채널에 **채널 보기·메시지 보내기·링크 삽입·파일 첨부·메시지 기록 보기** 권한을 줍니다. 관리자 전체 권한이나 Message Content 권한은 요구하지 않습니다. 파일 첨부는 차트·내보내기 전달에 사용합니다.
3. 아래 명령을 실행합니다. 등록은 지정 서버에 있는 이 앱의 Slash Command 목록을 교체하므로 앱을 PaperMarket 전용으로 사용합니다.

```powershell
npm run config:check
npm run register:commands
npm start
```

`config:check`는 설정 검증만 수행합니다. `register:commands`는 `DISCORD_GUILD_ID` 서버에 등록하고 `start`는 실제 Gateway에 연결합니다. 필수 설정이 빠지면 시작을 거절합니다. 저장소에 운영 자격증명은 없으며 실제 Discord 연결·등록·첨부/DM 전달 검증은 수행하지 않았습니다. 단계 5는 Slash Command 21개를 제공하며 새 명령을 사용하려면 명령 등록을 다시 실행합니다.

| 명령 | 사용 예와 동작 |
|---|---|
| `/setup` | `channel:#시장` - 서버 관리 권한으로 시장·고정 현황판 설정·복구 |
| `/help`, `/privacy` | 계좌 없이 모의투자 규칙·약관·처리 안내 확인 |
| `/open` | `age_14_plus:true agree_terms:true` - 각각 확인 후 최초금 10,000을 시장별 한 번 지급 |
| `/market`, `/status` | 현재 모의 시세·등락률·버전·운영 상태 조회 |
| `/economy` | 공개된 가상 금리·거시 지표·정책회의 기대와 최근 공시 조회 |
| `/financial` | `symbol:HGI` - 해당 기업의 마지막 공개 분기 실적·현금흐름·연간 전망 조회 |
| `/buy` | 시장가 `symbol:HGI quantity:1` 또는 `symbol:HGI budget:10000`; 지정가 `symbol:HGI quantity:1 order_type:LIMIT price:950 ticks:21` |
| `/sell` | 시장가 `symbol:HGI quantity:1` 또는 `symbol:HGI all:true`; 지정가 `order_type:LIMIT price:1100 quantity:1`; 스톱 `order_type:STOP price:900 quantity:1` (각 조건주문에 `symbol` 필수) |
| `/orders` | 미체결 우선 최근 최대 25건 중 4건을 표시하고 본인 주문을 취소; 취소하면 다음 조회에서 나머지 주문 확인 가능 |
| `/company` | `symbol:HGI` - 기업 상세·조정 기준가·원가격 변화·현재 세대·공개 재무 확인 |
| `/calendar`, `/news` | 이미 공개된 실적·금리·배당 일정과 공시; 공시는 4건씩 다음 페이지 조회 |
| `/chart` | `symbol:RVI series:PRICE scale:LINEAR ticks:252` - 원가격 또는 배당 포함 1주 총가치 PNG, 2~2,000틱·로그축 선택 |
| `/portfolio`, `/history` | 본인 자산·손익 및 체결·배당·이자·청산·조정 내역 4건씩 조회 |
| `/performance` | 총수익·최대낙폭·손익 기여 대조·개설 시점 CASH/HOLD8·시장 PM8 비교 |
| `/export` | `format:JSON` 또는 `CSV` - 본인 기록만 비공개 첨부, 페이지 상한 1,000건·첨부 합계 2MB |
| `/alerts` | `action:VIEW/WATCH/UNWATCH/PRICE/REMOVE/DM/READ` - 관심 종목·가격 조건·알림함·선택 DM 동의 관리 |
| `/close` | `confirmed:false`로 안내 확인, `confirmed:true`로 본인 계좌 종료 |

`/history`·`/export`의 다음 페이지 버튼은 본인 원장의 `(순번, 사건 ID)`를 함께 전달합니다. 같은 순번에 여러 원장 항목이 있어도 건너뛰거나 반복하지 않으며 서버가 본인 기록인지 확인합니다. `/export before_sequence`는 해당 순번보다 앞선 구간을 수동 선택하는 옵션입니다. 전체 이력을 이어 받을 때는 응답의 다음 페이지 버튼을 사용합니다. 뉴스는 같은 틱의 여러 공시를 구분하는 별도 공시 cursor를 사용합니다.

매매는 견적의 가격·수량·수수료·정산액을 보고 확인 버튼으로 확정합니다. 수수료는 양방향 0.1%, 수량 입력은 소수점 6자리까지입니다. 예산은 수수료를 포함합니다. 견적은 자산을 예약하지 않으며 30초 안에 확인해야 합니다. 시장이나 계좌 버전이 바뀌면 `/buy`·`/sell`로 새 견적을 받고 다시 확인합니다. 다른 참가자 수·매매량 때문에 가격이나 체결 수량을 조정하지 않습니다.

조건주문은 수량·조건가격을 입력하며 예산·전량 옵션을 함께 사용하지 않습니다. `order_type` 기본값은 `MARKET`, 매수는 `LIMIT`, 매도는 `LIMIT`·`STOP`도 선택할 수 있습니다. `time_in_force:TICK_COUNT` 기본 21틱 또는 `ticks:1`~`10000`, `time_in_force:UNTIL_CANCELLED`로 기간을 선택합니다. 취소할 때까지에는 `ticks`를 함께 넣지 않습니다. 유효기간 화면은 전체 시장 틱이고 실적·배당의 별도 경제 틱과 다를 수 있습니다.

확인 시 이미 조건을 충족하면 현재 확정가로 전량 체결하며 그 외에는 자산을 예약하고 새 확정 시세마다 평가합니다. 지정가 매수는 수량×조건가격+최대 수수료를, 매도·스톱은 주식 수량을 예약합니다. `/portfolio`에서 총액과 가용/예약을 구분합니다. 예약 현금은 총 현금에 포함되어 예치이자를 얻고 예약 주식도 배당 권리를 유지합니다. 예약 자산을 다른 주문에 중복 사용할 수 없습니다. 지정가의 개선 가격과 스톱의 갭 가격 모두 실제 확정 시세로 정산하며 스톱은 손실액을 보장하지 않습니다.

틱 경계는 만료→기업행동 취소→새 시세→조건 평가 순서입니다. 정확히 만료 틱에는 체결하지 않고 같은 계좌는 접수 순번으로 처리합니다. 배당락·교환·소멸은 해당 미체결 주문을 취소·예약 해제하며 단순 배당 지급일은 취소 사유가 아닙니다. 옛 주문을 새 회사로 자동 이전하지 않습니다.

개인 명령·버튼 응답은 비공개입니다. 공개 현황판에는 시장 정보만 표시합니다. 삭제된 현황판은 `/setup`으로 복구하고, 채널 이동은 새 참조 저장 후 이전 게시물을 이동 안내로 수정합니다. 이전 채널 권한 문제는 비공개로 안내합니다. 응답 전송이 실패해도 체결을 재실행하지 않으며 `/history` 또는 같은 확인 버튼으로 결과를 확인합니다.

계좌 종료 시 미체결 조건주문을 취소·예약 해제하고 원래 Discord 사용자 ID·개설 확인·개인 캐시·원본 확인 nonce·알림 설정/동의·알림함·연결 발송 작업·중복 방지 키·내보내기 접근 기록을 제거·무효화합니다. 접수된 조건주문·예약 전표·금융원장·성과·기준전략·서버 범위 가명 HMAC은 시장 존속기간 보관하며 재개설·초기금 재지급을 금지합니다. 전체 삭제와 구분하고 [정책·운영 확인 사항](docs/policy/README.md)에 보관·권리 요청 경로를 기록했습니다. 정책 v6를 표시하며 v1~v5 원본도 보관합니다. 이미 전달한 Discord 첨부·DM과 SQLite 이전 페이지·WAL·백업의 파기는 별도 운영 절차입니다. 이전 백업 복구 뒤에는 이후 종료·DM 철회를 운영자가 대조해 다시 반영해야 합니다.

## 가상 경제와 현금 이자

가상 연은 252틱, 월은 21틱, 분기는 63틱입니다. 가상 정책금리는 월별 회의에서 동결 또는 ±0.25%p로 움직입니다. 거시 지표에는 지속되는 경기 국면·평균회귀·독립적인 관측 오차를 반영합니다. 실제 시장 데이터나 금융기관과 연결하지 않습니다.

기업 매출·비용·외상채권·채무·수금·이자·세금·설비투자는 대응 전표로 기록합니다. 설비투자는 계획→지출→완공→후속 감가상각을 거치고 연구개발은 비용으로 처리합니다. 고정금리 부채는 계약금리를 유지하고 변동금리는 재설정일부터 새 정책금리를 적용합니다. 첫 실제 분기는 경제 63틱에 마감하고 HGI·DNL은 64, TLR·RVI는 65, NXC·VTR은 66, AUR·LMB는 67틱에 공개합니다. 초기 과거 실적은 합성 초기화 자료로 표시합니다.

가격은 공개 자료로 추정한 20분기 명목 FCFF 가치·시나리오·시장 기대·잔차로 결정합니다. 보통 가격 변동은 틱당 ±30%로 제한하고 임의의 최저가격이나 보호 반등은 두지 않습니다. 미공개 기업 상태·다음 분기 결과·서버 시드는 조회 응답이나 가격 모듈에 전달하지 않습니다. 가치 추정치는 정답 가격을 뜻하지 않습니다.

현금 예치 연이율은 `max(가상 정책금리 - 0.5%p, 0)`이고 일 실효이율로 환산합니다. 틱 시작에 금리를 고정하고 각 보유 구간의 현금×활성시간 비율로 이자를 발생시켜 틱말에 지급합니다. 거래 전후 현금을 따로 계산하며 틱 내부에서는 재복리하지 않습니다. 원자 단위보다 작은 이자 잔액은 정확한 분수로 이월합니다. `/portfolio`의 총자산에는 미지급 현금 이자가 한 번 포함되며 누적 지급액도 표시합니다.

기존 시험 시장에 경제를 도입할 때 현금·보유·취득원가·가격·시장 틱을 유지하면서 별도의 경제 0틱에서 시작합니다. 단계 2·3 경제 스냅샷은 기존 원문·해시를 검증한 후 메모리에서 새 기본값을 보완하며 역사 기록을 다시 쓰지 않습니다. `/economy`·`/financial`의 경제 진행·배당 표시는 **경제 틱**, 조건주문 만료와 `/calendar`·차트·원장 이력은 **전체 시장 틱**으로 읽습니다. 새 달력은 공개된 경제 일정을 시장 틱으로 바꾸어 표시합니다.

## 가상 사건과 공개 전망

사건 템플릿은 기업별 24개×8=192개, 거시(MAC) 24개, 기업 관계(XCO) 24개로 총 240개입니다. 계약·수요·비용·운영·설비·사고·자금·시장 믿음 등을 대상·기간·감쇠·적격 상태와 후속 프로젝트로 연결합니다. 직접 가격을 몇 퍼센트 올리라는 사건 지시는 없습니다. 가상 계약금은 매출 인식·현금 수금을 구분하고 설비 지출·감가상각과 연구/마케팅 비용의 회계 성격을 유지합니다.

사건은 실제 뉴스나 사용자 입력 수집이 아닙니다. 발생과 공개의 시차를 지키며 공개 전 실제 결과·예정 후속 단계는 가격과 사용자 조회에 전달하지 않습니다. 공개된 실제/예상/이전 값과 출처·확실성으로 전망을 조정합니다. 공개된 믿음은 감쇠하는 기대 경로에 반영하며 계약 발표금 전체를 현금·기업가치에 즉시 더하지 않습니다. 자세한 경계와 가정은 [ADR-0005](docs/ADR-0005-conditional-orders-events.md)에 기록했습니다.

## 배당과 청산

배당은 정상화 이익·지급 여력·누적이익의 한도 안에서 선언합니다. 선언 T의 권리는 T+3 틱 직전 보유량으로 확정하고 T+5에 지급합니다. 확정 후 매도해도 권리는 남으며 이후 매수한 수량은 해당 권리를 얻지 못합니다. `/financial`은 배당 일정, `/economy`는 기업행동 공시, `/portfolio`는 명목·현재 평가·실제 지급을 구분합니다. 지급은 권리를 현금으로 바꾸며 이중 수익으로 합산하지 않습니다. 현금 정산은 확정 기업 지급 총액과 발행주식 수의 정확한 분수를 사용하고 원자 미만 잔액을 이월합니다.

기업 부실은 현금 여력·만기·연체·재무 위반으로 판단하며 낮은 주가만으로 청산하지 않습니다. 증자는 기업 현금과 발행주식 수를 함께 늘립니다. 청산 시 옛 종목의 거래와 이전 견적을 중단하고 기존 수량·취득원가를 회수권으로 이전합니다. 청산 비용→담보채무→선순위→배당을 포함한 후순위→보통주의 순서로 정산하며 회수 0도 최종 손실로 남깁니다.

같은 틱에서 같은 범주의 새 회사를 독립 발행사·상장 ID와 새 심볼(HGI2 등)로 편입하여 활성 슬롯 8개를 유지합니다. 새 회사는 1,000에서 시작하지만 옛 보유자에게 주식·보상금·손실 초기화를 제공하지 않습니다. 배당 부착 가치와 계속기업 가치를 분리해 배당락 후 일반 변동 ±30%를 적용합니다. 양쪽 가치가 모두 0인 활성 종목의 참조 충돌은 틱 전체를 롤백하고 시장을 중단하여 무료 매수를 차단합니다. 상세 가정은 [ADR-0004](docs/ADR-0004-corporate-actions.md)에 기록했습니다.

## 성과·알림·자료 내보내기

단계 5의 기준전략은 본인과 같은 개설 시점·10,000포인트에서 시작합니다. HOLD8은 같은 매매 비용으로 최초 8종목을 매수 후 보유하고 CASH는 예치이자를 받습니다. 기존 계좌의 최초 틱 부분 보유시간을 복원할 수 없으면 그 부분의 이자를 제외했다고 표시합니다. PM8은 도입 시점부터 별도 자기자금으로 운용하며 21틱마다 활성 8종목을 재조정합니다. 소멸 종목의 손실·회수권을 보존하고 새 주식을 무료 지급하지 않습니다.

성과는 지급 전 배당·청산 권리와 발생 이자를 포함하는 순자산으로 대조합니다. 수수료는 매매 원가·실현손익에 이미 반영되어 다시 빼지 않습니다. 최대낙폭의 표본은 개설 원금·완료된 틱 말 순자산·현재 순자산이며 틱 내부 최저가는 포함하지 않습니다. 종목 총가치 차트는 원래 1주의 가격+배당/청산 지급현금+권리 평가이고 현금이자·재투자·거래 비용은 제외합니다. 퇴역 세대의 차트와 신생 기업 차트를 연결하지 않습니다.

알림 기본 전달 경로는 `/alerts`의 본인 알림함입니다. DM은 기본 꺼짐이며 `action:DM dm:true`의 별도 선택 동의 뒤에만 보내고 전송 직전에도 동의를 확인합니다. `dm:false`로 철회하면 대기 발송을 취소하고 이미 보낸 메시지는 회수하지 않습니다. 중요한 공시·보유 배당 권리/지급·조건주문 체결/종료·가격 통과를 금융 커밋과 함께 기록하고, 외부 전송은 별도로 재시도합니다. 응답 손실 뒤 동일 알림이 재전송될 수 있으나 금융 효과는 재실행하지 않습니다. 알림함은 최근 1,000건이며 관심 종목·가격 조건은 각각 최대 20개입니다. 옛 listing ID에 연결되어 후속 세대로 이전하지 않습니다. 가격은 해당 방향을 통과할 때 한 번 알리고 반대편으로 돌아온 후 다시 준비합니다.

CSV는 계좌·이력·보유·권리·성과·체결 비용·설정/동의·최근 알림을 8개 파일로 제공하고 전체 첨부는 2MB 이내로 제한합니다. 수식 실행을 막도록 모든 셀을 인용·이스케이프하며 JSON/CSV 모두 시드·미공개 경제 상태·확인 토큰·HMAC 연결값을 제외합니다. 봇은 첨부 파일을 메모리에서 생성하고 디스크에 저장하지 않습니다. 내보내기 접근 기록은 최근 1,000건이며 계좌 종료 때 알림 설정·알림함·전송 작업과 함께 제거합니다. 기존 가명 금융원장·기준전략·성과 표본은 무결성 기록으로 남습니다.

## 실행과 복구

Gateway는 비공개 초기 응답을 마친 뒤 백엔드를 기다립니다. SQLite·금융 계산은 전용 Worker의 단일 작성자에서 처리하고 주문·체결·현금·수량·원가·버전을 한 트랜잭션으로 커밋합니다. 조회는 현재 본인 원장을 읽으며 개인 조회 응답을 캐시로 저장하지 않습니다. 현황판 전송은 금융 갱신과 분리하고 같은 시장의 대기 스냅샷은 최신값으로 합칩니다. Worker 비정상 종료는 봇 정리와 오류 종료로 연결합니다.

같은 DB를 여러 프로세스로 실행하면 작성자 잠금으로 거절합니다. 정상 종료는 `Ctrl+C`를 사용합니다. 죽은 PID의 잠금은 소유권 재확인 후 복구하지만 손상된 잠금·`.writer-lock.acquire`가 남으면 시작을 거절합니다. 모든 프로세스가 종료됐는지 확인한 운영자가 잠금 파일만 점검해야 합니다. DB·WAL·계좌 키를 지워 해결하지 않습니다. 오프라인 틱은 소급 생성하지 않고 마지막 체크포인트의 남은 시간을 복원합니다.

요청 보호는 사용자당 동시 대기 8건·전체 256건·순간 10건·초당 5건 회복입니다. 일일 매매 횟수나 거래량 제한은 없습니다. 로그에는 상수 진단 코드·시각과 허용한 수치 집계만 남기고 토큰·개인 원문·SQL·예외를 출력하지 않습니다.

단계 6의 운영 Worker는 일관된 SQLite 스냅샷·전체 원장/해시 검증·AES-256-GCM 암호화 백업을 처리합니다. 시간별 생성, 선택한 별도 경로의 일별 복제, 월별 복구 리허설을 점검하며 복원은 새 파일만 생성합니다. `npm run health:check`는 Discord 연결 없이 읽기 전용 집계를 점검합니다. 백업 CLI·복구 절차·키/경로·로그와 장애 대응은 [운영 안내](docs/OPERATIONS.md)에 기록했습니다.

모형 배치는 같은 preset으로 여러 번 실행하여 checkpoint에서 이어갑니다. 짧은 `pilot` 완료는 200개×10,000틱 reference나 각 100,000틱 drift의 완료가 아닙니다. 부하의 합성 공개 가격 projection 800,000행도 생산 경제/권리/기준전략의 10,000틱 이력을 대신하지 않습니다. 실행별 검증 결과는 [검증 자료](artifacts/milestone6)에 보관합니다.

금액은 10⁻¹²포인트 단위 BigInt이고 DB에는 정규화된 정수 문자열로 저장합니다. 가격·비율 계산은 50 유효자리 Decimal이며 정산은 정확한 BigInt 분수로 계산합니다. 아주 작은 양수 가격도 보존하고, 정산 표현 범위 밖 거래는 오류로 거절합니다. 가격을 0 또는 임의 최저가격으로 바꾸지 않습니다.

사용자 수량 입력은 10⁻⁶주 단위이고 내부 권리 수량은 더 작은 소수를 보존합니다. 분수 잔액은 분자·분모 정수 문자열로 직렬화합니다. 금융 값에 JavaScript `Number`나 SQLite `REAL` 합산을 사용하지 않습니다. 숫자 표현 상한과 기초 재무 분해 가정은 [초기화 결정 기록](docs/ADR-0001-foundation.md)에 명시했습니다.

저장 계층은 서버 내부 전용입니다. 호출자의 ID·권한·수신시각은 Gateway의 인증된 Interaction으로 결정하고 서버에서 다시 검증합니다. 현재 테스트는 합성 ID와 임시 DB만 사용합니다. 운영 데이터·키·시드는 저장소에서 제외합니다. 체결·Discord 결정은 [ADR-0002](docs/ADR-0002-broker-discord.md), 경제·가격 가정과 버전은 [ADR-0003](docs/ADR-0003-economy.md)에 기록했습니다.
